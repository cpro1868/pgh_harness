# 文档管理规范

## 目录结构

```
docs/
├─ README.md                    # 文档地图（本文件索引入口）
├─ 工作进展记录.md               # 按日期倒序的工作日志
├─ 规范/                        # 细分规范（编码/测试/Git/文档）
│   ├─ 编码规范.md
│   ├─ 测试规范.md
│   ├─ Git提交规范.md
│   └─ 文档管理规范.md
├─ superpowers/specs/           # 设计规格（概要/详细设计）
│   └─ YYYY-MM-DD-<topic>-design.md
└─ 阶段-*/                      # 生命周期各阶段交付物
    ├─ 阶段-1-需求/
    ├─ 阶段-2-设计/
    ├─ 阶段-3-实现/
    ├─ 阶段-4-测试/
    └─ 阶段-5-交付/
```

## 命名

- 设计文档：`YYYY-MM-DD-<kebab-topic>-design.md`
- 规范文档：`<领域>规范.md`（中文）
- 阶段文档：`阶段-<N>-<阶段名>/<交付物>.md`

## 更新纪律

| 时机 | 动作 |
| --- | --- |
| 关键确认后 | 更新 `CONTEXT.md`（只写结论，不写过程） |
| 会话开始 | 读 `SESSION.md` 恢复上下文，登记本次目标 |
| 会话结束/中断前 | 更新 `SESSION.md`（已完成/进行中/下一步/阻塞点） |
| 完成任一里程碑/任务 | 更新 `docs/工作进展记录.md`（**按时间维度记录**，含做了什么、关键决策、依赖变更、下一步） |
| 设计定稿/变更 | 更新 `docs/superpowers/specs/` 中的对应文档 |
| 生命周期阶段完成 | 在 `docs/阶段-*/` 下建交付物文档 |
| 新增文档 | 更新 `docs/README.md` 索引 |

### 工作进展记录格式

- 按日期倒序，同日内按时间倒序（最新在最上方）
- 时间格式：`YYYY-MM-DD HH:MM`（24 小时制，本地时间）
- 每条记录含：**做了什么**、**关键决策**、**依赖变更**（若有）、**下一步**
- 粒度：一个「可交付的单元」一条（如「完成某功能」「确认某决策」「建立某规范」），不写「在改代码中」这种中间态

## 冲突处理

- 代码与文档冲突：先改文档再改代码，或在文档中标注偏离原因。
- 多个文档对同一规则有分歧：以 `AGENTS.md` 为最高准则，其他文档向其看齐。

## 生命周期阶段（不可跳过）

1. **需求**：需求分析、用户故事、验收标准
2. **设计**：概要设计、详细设计（见 `superpowers/specs/`）
3. **实现**：里程碑计划、代码、单测
4. **测试**：测试报告、验收记录
5. **交付**：发布说明、README、部署文档
