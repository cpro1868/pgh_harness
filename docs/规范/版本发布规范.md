> 归属规范：项目工程交付规范  
> 前置铁律：**零 Native 编译、绝对禁止 MSVC / VS C++ 依赖、MIT/Apache-2.0 纯净版权**

---

## 1. 物理目录拓扑规范

系统根目录下划定四大核心物理目录，严禁文件混杂：

| 目录 | 角色定位 | 包含内容 | 严禁存放内容 |
| :--- | :--- | :--- | :--- |
| **`packages/`** | **核心共享库与插件源码** | 内核 (`kernel`)、协议 (`protocol`)、业务调度 (`core`)、标准插件 (`plugins/*`) | 绝不存放编译产物、运行日志、测试临时沙箱 |
| **`apps/`** | **独立部署应用源码** | 后端主服务 (`apps/server`)、React 前端 (`apps/web`) | 绝不存放构建压缩产物、物理数据库文件 |
| **`scripts/`** | **开发与工程运维脚本** | 离线自检 (`self-check.ts`)、跨平台开发启停 (`start-dev.ps1`, `stop-dev.ps1`, `start-dev.sh`, `stop-dev.sh`) | 绝不存放具体业务逻辑实现 |
| **`dist/`** | **发布构建输出 (Release Build)** | 编译压缩后的 `dist/server.js`、`dist/web/` 静态资源、单命令分发包 | 绝不手动修改其中文件，仅由构建自动化产出 |

## 3. 发布版本交付形态 (Zero-Native Delivery)

为实现极致的跨平台与开箱即用，系统采用 **零 Native 极简自包含分发**，杜绝重型外部包袱：
1. **npx / 纯 Node 一键运行**：
   ```bash
   npx harness-agent
   # 或源码运行
   pnpm start
   ```
2. **构建发布产物 (`dist/`)**：
   - 执行 `pnpm build`：
     - 后端服务 `apps/server` 打包编译至 `dist/server.js`；
     - 前端应用 `apps/web` 打包编译至 `dist/web/` 静态目录，由 Fastify 静态托管；
   - 依赖纯 Node 22+ 内置环境（`node:sqlite` + `undici` + 原生 `fetch`），单一端口（3000）自包含交付。
3. **免 Docker 强依赖**：摒弃复杂的容器网络映射与 Python/Docker 守护进程，本地原生极速秒级唤醒。

## 4. 自动化版本发布与打标清单 (Sprint Release Checklist)

在任何 Sprint 宣布结项、版本 Tag 打出或正式发布前，必须依次满足以下硬性门禁：

1. **Sprint Demo 业务演示通过**：必须使用启动脚本（`start-dev.ps1` / `start-dev.sh`）真实拉起，演示通过该 Sprint 承诺的全部 Shippable 业务特性；
2. **测试驱动验收 100% 绿灯**：
   - `pnpm test`：全部已实现的自动化单测与集成测试必须 100% 通过，断言零失败；
   - `node scripts/self-check.ts`：纯离线环境下全链路自动化闭环自检，耗时严格 < 5 秒，退出码为 0；
3. **静态代码质量门禁**：
   - `pnpm lint`：零 error，零 warning；
   - `pnpm typecheck`：`tsc --noEmit` 严格类型检查，零 any；
4. **编译构建成功**：
   - `pnpm build`：成功产出 `dist/` 完整分发包；
5. **版本打标与日志对齐**：
   - 更新根目录与各 package 的 `package.json` 中的 `version` 字段；
   - 执行 `git tag -a <version> -m "<sprint summary>"`；
   - 在 `docs/工作进展记录.md` 登记版本发布条目、核心可演示特性与依赖审计。
