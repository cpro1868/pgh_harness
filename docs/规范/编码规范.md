# 编码规范

> 从 AGENTS.md 第 4 节细化。

## TypeScript

- `strict: true`，禁止 `any`（确需时用 `unknown` + 收窄）。
- 所有函数必须有返回类型；公开 API 必须有 JSDoc（参数 + 返回值 + 异常）。
- 不导出的类型/函数不加 `export`。

## 命名与目录结构

- 文件：`kebab-case.ts`；类型：`PascalCase`；函数/变量：`camelCase`；常量：`UPPER_SNAKE_CASE`。
- 架构包分层：
  - 内核包：`packages/kernel`（Cordis-like 微内核）
  - 协议包：`packages/protocol`（前后端同构 DTO、Events、SSE 契约）
  - 核心调度：`packages/core`（ReAct Loop、上下文治理、权限流水线）
  - 插件包：`packages/plugins/<kebab-case>`
  - 后端服务：`apps/server`（Fastify、SSE 流网关、单实例锁）
  - 前端业务切片：`apps/web/src/features/{chat,config,pipeline,workflow}`（敏捷三阶段切片）
  - 自检工程脚本：`scripts/`（`self-check.ts` 等）

## 错误处理

- 信任边界（工具入参、HTTP 请求、文件路径、密钥）必须校验。
- 错误不吞：要么写日志，要么上抛；绝不 `catch {}` 空块。
- 自定义错误带 `code` 字段，便于前端/调用方区分。

## 注释

- **不加注释**，除：
  - `ponytail:` 有意简化标注（注明上限与升级路径）；
  - 公开 API 的 JSDoc；
  - 复杂的算法/协议实现（如 SSE 解析、加密格式）可加简短说明。

## 开源参考与代码复用规范 (杜绝重复造轮子)

- **开工前查参考库**：在动手编写任何模块或算法前，必须首先检索 `reference/` 下的成熟开源库（`opencode`, `bpmn-moddle`, `xyflow`, `dify`）。
- **能复用直接 Copy / 适配复用**：已有的成熟算法、正则、类型定义或纯函数，优先直接 Copy 过来或做最小化适配，绝不从零闭门造车。
- **无法直接复用则吸收其状态机设计**：若技术栈不同（如 Python 转 TS），深入吸收其边界条件与状态机流转设计。
- **最短工作代码优先 (Shortest Working Diff)**：只要符合本项目既定设计与测试门禁，复用存量优秀代码为最高荣光。

## 依赖与环境合规

- **绝对零 MSVC 与 Native 编译（最高铁律）**：严禁引入任何需要 MSVC、Visual Studio C++ 编译链或 `node-gyp` 触发本地编译的依赖包（包括带 `bindings.gyp` 的包）。
- **版权与许可证合规**：绝不引入存在 GPL 传染性、协议风险或版权纠纷的包；仅使用 MIT、Apache-2.0、BSD 或纯 TypeScript/Node 内置标准库。
- **预置工具与 Skills 策略**：在项目研发启动前，允许并推荐提前安装相关开发工具链与标准 Agent Skills（如 `pwsh`、TypeScript 基础库等），保障研发效率。
- 新增依赖必须写进 `docs/工作进展记录.md` 的「依赖变更」节。
- 优先用 Node 标准库；能用 `node:*` 就不装包。

## 安全红线

- 密钥/Token 不入库明文、不进日志、不回传前端。
- 文件工具不越 workspace 根；`fetch_url` 过 SSRF 检查。
- 模型输出渲染必须 sanitize。
- 绑定非回环地址必须强制 `HARNESS_ACCESS_TOKEN`。
