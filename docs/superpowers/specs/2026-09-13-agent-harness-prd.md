## 1. 背景与愿景

### 1.1 背景

AI 编码 Agent 已成为主流开发工具，但现有产品存在明显缺陷：

- **厂商锁定**：Claude Code / Cursor / Codex 都绑自家模型，换模型成本高，无法自由选择
- **黑盒执行**：不知道 Agent 发了什么 prompt、看了什么文件、为什么改错、花了多少钱
- **数据隐私**：代码必须传到云端，敏感项目不敢用
- **工具不可控**：Agent 乱删文件、乱执行命令，没有细粒度权限控制
- **上下文爆炸**：长会话容易超限，压缩策略不透明，出问题没法回放
- **不可复现**：Agent 行为像开盲盒，无法复现「当时模型看到了什么」

### 1.2 愿景

做一个**「能自己掌控的编码 Agent」**——不被厂商锁定、数据不出本机、能接任意模型、能看每一步在干什么、能精确控制每个工具的行为、能回放每一次执行。

## 2. 目标用户与痛点

### 2.1 目标用户

**独立开发者 / 小团队工程师**，特征：
- 有个人/小团队代码库，可能包含敏感项目
- 希望用最强模型（GPT-4/Claude/DeepSeek）但不想被绑定
- 需要理解 Agent 的行为（调试、审计、学习）
- 重视数据隐私（代码不出本机）
- 有一定技术能力，能配置环境变量、跑本地服务

**非目标用户**：
- 纯小白用户（需要零配置开箱即用的桌面应用）
- 大型企业（需要多用户权限管理、审计合规、SSO）
- Agent 开发者（需要 benchmark 框架，可能后续扩展）

### 2.2 核心痛点

| # | 痛点 | 现状 | 本项目解决方式 |
| --- | --- | --- | --- |
| P1 | **厂商锁定** | Claude Code 只能用 Claude，Cursor 绑自家模型 | 统一 Provider 接口，接任意 OpenAI 兼容端点，可自定义适配器 |
| P2 | **黑盒执行** | 不知道 Agent 看了什么、改了什么、为什么失败 | 事件日志为唯一真相，可查看轨迹、回放、fork；工具调用卡片展示参数与结果 |
| P3 | **数据隐私** | 代码必须传到云端 | 本地部署，数据存本机 SQLite，密钥加密存储 |
| P4 | **工具不可控** | Agent 乱删文件、乱执行命令，事后才发现 | 权限规则表（工具 + 参数模式 + allow/ask/deny）+ 审批闸门 + 沙箱约束 |
| P5 | **上下文爆炸** | 长会话超限，压缩不透明，工具输出撑爆窗口 | 自动 token 计量、压缩、结果裁剪、大输出落盘（Spill），全部可配置 |
| P6 | **不可复现** | Agent 出错后无法复现，没法调试 | `request/context` 快照 + 确定性投影，可 100% 复现「当时模型看到了什么」 |
| P7 | **工具链缺失** | 需要自己写 shell 脚本、读文件、跑测试 | 内置编码工具集（文件/搜索/持久 shell/后台任务）+ MCP 客户端接入生态 |
| P8 | **权限粒度粗** | 要么全开要么全关，没法「只读 git 命令免问，写操作每次问」 | 规则表支持参数模式匹配，预设（只读/编辑/全权）一键切换 |
| P9 | **会话不可管理** | 长会话没法分叉、没法导出、没法搜索 | 会话树、fork/replay、FTS 搜索、JSON/Markdown 导出 |

## 3. 产品定位与边界

### 3.1 定位

**一句话**：可插拔的编码 Agent 运行时 + Web 界面，让开发者用任意模型、在本地、可控地完成编码任务。

**对比**：
- vs Claude Code：不锁模型，可插拔，开源
- vs Cursor：不是编辑器插件，是独立运行时 + Web 界面，可接任意前端
- vs Aider：有 Web UI，有权限控制，有上下文治理，不只是 CLI
- vs dsh（DeepSeek Harness）：功能类似，但我们从零建，接口与 Cordis 对齐，可兼容其插件生态

### 3.2 边界（本期不做）

- **不做**：登录/多用户（仅预留 `user_id`）、桌面端/IDE 插件、移动端 App、语音输入、computer use、浏览器自动化
- **不做**：订阅制 OAuth 鉴权、插件市场、社区会话数据集共享
- **预留但本期不做**：ACP 适配、定时/Webhook 触发、多模态输入、LSP 诊断回灌

### 4.2 关键交互流程

**典型场景：修一个 bug**

1. 用户在 Web 界面选择 workspace（如 `G:\Projects\my-app`），新建会话
2. 输入「这个函数在边界条件抛错，请修复并补测」
3. Agent 通过 `glob`/`grep`/`read_file` 定位问题，中途用 `todo_write` 拆解任务
4. Agent 通过 `edit_file` 改代码、改测试
5. Agent 通过持久 shell 跑测试命令（**审批弹窗**：展示 `npm test`，用户点「批准」）
6. Agent 用 `git diff` 查看改动，整理结果
7. 用户在 **DiffCard** 上审阅每个文件的修改，可接受/拒绝
8. 用户满意后，Agent 用 `git commit` 提交（再次审批）或生成 commit message 建议

**关键交互点**：
- 流式输出：助手回复逐字显示
- 工具卡片：每次工具调用可折叠看参数与结果
- 审批弹窗：危险操作（写文件、跑命令）必须用户批准
- 任务清单：Agent 拆解任务时实时更新进度
- 轨迹视图：可随时查看「模型当时看到了什么」

## 5. 非功能需求

### 5.1 性能

- **启动**：服务启动 < 2s（不含 LLM 调用）
- **响应**：首次 token 输出 < 3s（取决于模型），工具执行 < 5s（本地命令）
- **并发**：单用户，最多同时 3 个会话有后台任务
- **上下文**：支持 128K token 窗口，自动压缩到 90% 阈值以下

### 5.2 可用性

- **崩溃恢复**：进程崩溃后重启，会话可恢复，中断的回合可续
- **断线重连**：浏览器刷新/断网后，进行中的回合可续传
- **离线可用**：本地模型（Ollama）完全离线可用

### 5.3 安全

- **数据不出本机**：所有数据存 `data/harness.db`，密钥加密
- **权限控制**：文件工具不越 workspace 根；命令执行需审批；SSRF 防护
- **网络暴露**：默认只监听 `127.0.0.1`；绑外网必须设访问令牌
- **审计**：事件日志即完整审计轨迹，可导出

### 5.4 兼容性

- **平台**：Windows 11 / Linux / macOS（优先 Windows）
- **Node**：≥ 22.16.0（需要 `node:sqlite`）
- **浏览器**：Chrome / Edge / Firefox 最新版

### 5.5 可维护性

- **零 Native 编译**：不依赖 `node-gyp`，任何机器 `pnpm install` 即可跑
- **插件化**：新增工具/Provider/存储后端不改核心代码
- **测试覆盖**：关键模块必须有单测，集成自检脚本可一键验证

## 6. 验收标准

### 6.1 本期验收（M1–M9 完成后）

**必须跑通的端到端场景**：

1. **安装与启动**
   - `npx @harness/web web` 一条命令启动，浏览器自动打开
   - 在设置页填入 `baseURL + apiKey`，自动发现模型列表，选择一个模型

2. **真实编码任务**
   - 选择一个真实中小型 GitHub 项目（如一个 Node/TS 或 Python 项目）作为 workspace
   - 提交一个 issue 描述（如「某个函数在边界条件抛错，请修复并补测」）
   - Agent 自主定位问题、改代码、改测试、跑测试（带审批）
   - 最终在 DiffCard 上审阅改动，生成 commit message 或直接 commit

3. **权限与安全**
   - 尝试让 Agent 读取 workspace 外的文件 → 被拒绝
   - 尝试让 Agent 执行 `rm -rf` → 被拒绝或需要审批
   - Agent 写入文件前必须先读过该文件

4. **上下文治理**
   - 进行一次长会话（20+ 轮工具调用），观察自动压缩是否触发
   - 工具输出超过阈值时，观察 Spill 落盘是否生效

5. **会话管理**
   - 刷新浏览器，进行中的回合可续传
   - 崩溃后重启，会话可恢复
   - 导出会话为 JSON/Markdown

6. **可追溯**
   - 打开轨迹视图，查看任意一个 Step 时模型看到的完整上下文
   - Fork 一个会话到指定 seq，继续对话

### 6.2 明确不验收

- 多用户权限管理
- 桌面端/IDE 插件
- 插件市场
- 多模态输入（图片/文件上传）

---

### 6.3 多智能体协作验收标准

1. **子任务委派 (模式B)**：在聊天界面开启开关后，主 Agent 能够调用 `spawn_agent` 创建子 Agent 调查代码，子任务完成后产物精炼展示并汇入主对话。
2. **角色流水线 (模式A)**：选择「Feature 开发流水线」，依次触发需求分析 Agent、编码 Agent 与测试 Agent，并在阶段 Gate 点支持人工确认批准。
3. **BPMN 流程引擎 (模式C)**：支持加载 BPMN 2.0 XML 流程模型，支持排他网关根据测试通过率自动分流到「部署节点」或「打回修改节点」。

---

### 6.4 记忆与经验治理验收标准 (MOD-11)

1. **提取模式切换**：支持在「全自动静默提取」与「半自动人工确认」之间切换，界面明确展示两种模式适用场景。
2. **四大存储策略支持**：
   - 未启用模式 (Disabled)：完全不落盘、不注入；
   - 纯 Markdown 模式：生成 `.harness/memory.md`，可提交 Git 仓库；
   - 本地 SQLite 模式：基于 Node 原生 `node:sqlite`（零 Native），支持自定义相对或绝对路径，开启 FTS5 全文索引；
   - Markdown + 向量双轨模式：以 `.harness/memory.md` 为真相源，挂载本地 Embedding 计算切片向量。
3. **受控存储变更与数据迁移向导**：
   - 杜绝主界面随意即时切换；
   - 提供向导明确支持「全新起步，丢弃测试数据 (自动生成 .bak 备份)」与「平滑数据无损迁移 (原子事务+SHA-256去重)」精准分流。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `node:sqlite` 在 Node 22.x 标记 experimental | API 可能变动 | 锁定 Node 22.16+，写薄抽象层便于切换 |
| 插件内核自研复杂度高 | 拖慢进度 | 接口与 Cordis 对齐，必要时可切换 |
| 上下文压缩质量不可控 | 压缩后丢失关键信息 | 保留尾部最近轮次不压缩；压缩摘要可被再次压缩；用户可手动触发 |
| 权限规则表太复杂 | 用户不会配 | 提供预设（只读/编辑/全权）一键切换，规则表为高级选项 |
| 审批打断流程 | 用户频繁被打断烦 | 支持「本会话内始终允许该工具」；预设控制粒度 |

## 9. 成功指标（发布后 3 个月）

- **可用性**：至少 10 个真实用户在日常编码中使用
- **稳定性**：崩溃恢复成功率 > 95%
- **成本**：单次会话平均花费 < $0.5（取决于模型）
- **性能**：P95 首次 token 延迟 < 5s
- **满意度**：用户愿意推荐给同行（NPS > 40）
