# PG Harness 客户端 / 服务端（管理端）职责边界

> 确立日期：2026-10-28
> 核心原则：**客户端不需要登录即可使用全部本地功能**（对齐 DeepSeek Harness 模式）。只有连接服务端（管理端）时才需要登录。

---

## 1. 客户端（Client）—— 用户使用端

当前 v1.x 的全部功能 + v2.0 新增的客户端功能。

### 包含

| 模块 | 功能 |
| --- | --- |
| 主会话工作台 | 对话、工具执行、SSE 流式、输入建议（/skill @文件） |
| 需求探索（MOD-17） | 项目文件夹、自由讨论、Agent 引导、分块/任务/PRD |
| 角色流水线 | 多阶段 Agent 编排 |
| BPMN 工作流 | 流程图设计器 + 引擎执行 |
| 模型选择 | Provider 分组下拉 |
| Token 统计 | 轮数/步数/tok·s/缓存命中率 |
| 欢迎向导 v2 | 首启/引导双模式 |
| 撤销回滚 | Revert Turn |
| 语音播报 | Web Speech API |

### 数据存储

- **客户端本地 SQLite**（`~/.pg_harness/pgh.db`）
- 会话 / 事件 / 工作区 / Provider / Pipeline / BPMN / 需求探索（MOD-17 的 7 张表）
- **不需要 owner_id**（客户端是单用户的）
- 不需要登录（打开即用）

### Agent 执行

- Agent 在**客户端本地进程**运行（TurnLoop + 工具沙箱在本机）
- 模型调用由客户端直接发起（配置 Provider 即可）

### 登录

- **不需要登录**
- 只有连接服务端（管理端）时才需要登录

---

## 2. 服务端 / 管理端（Server / Admin）—— 统一管理端

v2.0 新增的企业级管理功能。部署在企业服务器或云上，管理员使用。

### 包含

| 模块 | 功能 |
| --- | --- |
| 用户管理 | 用户注册/禁用/重置密码/角色分配 |
| SSO 对接 | OIDC / LDAP / 飞书 / 钉钉适配器配置 |
| Git 仓库管理 | Git 平台连接（GitHub/GitLab/Gitee/自建）、Token 管理 |
| Jenkins 集成 | Jenkins 连接、任务管理、构建历史 |
| CI 闭环管理 | 构建-回灌规则配置、闭环轨迹查看 |
| 审计日志 | 全平台操作审计、导出、SIEM 对接 |

### 数据存储

- **服务端数据库**（PostgreSQL 或 SQLite，可插拔）
- 用户表 / 认证会话 / 审计日志 / Git 连接配置 / Jenkins 连接配置
- 多用户（管理端是多用户的，有 owner_id / RBAC）

### 登录

- **需要登录**（管理员账号或 SSO）
- 客户端连接服务端时需要提供凭据

---

## 3. 客户端 ↔ 服务端的连接关系

```
客户端（用户本机）                    管理端（服务器）
┌──────────────────┐               ┌──────────────────┐
│  本地 SQLite      │               │  PostgreSQL/SQLite│
│  本地 Agent 执行  │               │  用户/角色/SSO     │
│  本地工具沙箱     │               │  Git/Jenkins 配置  │
│  无需登录         │               │  审计日志          │
│                   │   可选连接     │                   │
│  ──── 登录后可获取 ──────────→  │  Git Token 分发    │
│  Jenkins 触发指令 ──────────→  │  构建触发          │
│  审计日志上报   ──────────→  │  审计汇总          │
└──────────────────┘               └──────────────────┘
```

- 客户端**离线可用**：不连接管理端时，全部本地功能正常使用
- 客户端**连接管理端后**：可获取 Git Token / 触发 Jenkins / 上报审计——增强功能
- 连接管理端时需登录（管理员分配账号或 SSO）

## 5. 对 MOD-17 需求探索模块的影响

**结论**：MOD-17 是**纯客户端功能**——

- 7 张数据表（requirement_chunks / work_activities / chunk_relations / activity_chunk_links / tasks / next_steps / decision_log）存**客户端本地 SQLite**
- **不需要 owner_id**（客户端单用户）
- **不需要登录**（打开即用）
- Agent 在**客户端本地**执行（需求分析师角色）
- 多 Agent 讨论时每个 Agent 的模型配置由用户在客户端设置
- 产出的 PRD.md / decisions.md / tasks.md 落盘到**本地工作区**的项目文件夹
