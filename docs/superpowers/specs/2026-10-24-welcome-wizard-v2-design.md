# 首次启动欢迎向导（Welcome Wizard v2）设计

- 日期：2026-10-24（v2.1 同日增补双模式设计）
- 状态：待用户审阅
- 关联：WBS-01-08-04（破冰向导，BL-06 已闭合的第一版）的全面升级；`run-chat.html` 既有 `#wizard-modal`

## 1. 背景与问题

现有一分钟破冰向导（2 步弹窗）已能完成"接模型 + 选工作区"，但存在五个体验缺口：

1. 纯表单弹窗，无产品价值引导——新用户不知道 PGH 是什么、能干什么；
2. 进度不落盘——步骤 1 填一半刷新即丢，无法从中间继续；
3. 跳过后无重跑入口——`skipWizard()` 落 `wizardCompleted=true` 后只能去各设置页零散配置；
4. 完成不校验——工作区路径填错也能"完成破冰"，进工作台才发现问题；
5. 完成页无后续指引——不知道之后在哪里加更多模型/工作区。

## 1.1 双模式定位（v2.1 增补，用户明确）

向导不只是"首次启动的一次性流程"，而是**常驻的系统引导能力**，两种模式：

| 模式 | 触发条件 | 屏序差异 | 预填行为 | 落盘影响 |
| --- | --- | --- | --- | --- |
| **首启模式**（First-Run） | 系统无任何 Provider 且无任何工作区（`needsWizard=true` 自动弹出） | 完整四屏（欢迎 → 模型 → 工作区 → 完成） | 空表单 + 默认示例值 | 完成后置 `wizardCompleted=true` |
| **引导模式**（Guided Re-run） | 用户主动触发（⚙️ 设置菜单「🧭 运行向导」或帮助入口） | **跳过屏 0**，直接进屏 1，屏 3 的"接下来你可以"替换为「回顾已完成配置」提示 | **预填当前实际配置**（已存的 Provider/工作区直接回显，可改可跳过） | 不改 `wizardCompleted`（已是 true），仅更新对应配置 |

双模式统一规则：
- 引导模式下每个已有配置项显示 ✅ 徽标与「保留现有配置」快捷按钮（一键跳过该步）；
- 引导模式中途退出（关闭/跳过）**不影响任何已存配置**——向导只做增量引导，绝不清空；
- 两种模式共用同一组件与状态机，仅入参（`mode: 'first-run' | 'guided'`）与预填数据不同；
- 价值卡片（屏 0）在引导模式跳过，但欢迎页头部保留一行"第 N 次运行向导"的上下文提示。

## 2. 目标（用户确认口径）

- **方案 A 全屏向导**：全屏欢迎页（产品价值卡片）+ 三步配置（模型 → 工作区 → 完成确认），每步落盘可续，顶栏设置入口可重跑；
- 完成校验前置：工作区路径存在性、Provider 探测成功才允许下一步；
- 完成页给出"之后去哪里加更多"的指引；
- 不改变既有后端 API 语义（复用 `needsWizard` / `wizardCompleted` / `POST /api/settings/section`），纯前端重构 + 一个进度存取小扩展。

## 4. 交互与状态设计

### 4.1 触发逻辑（双模式）

| | 首启模式 | 引导模式 |
| --- | --- | --- |
| 触发 | 页面加载 → `checkBootstrap()` → `needsWizard=true` | ⚙️ 设置菜单「🧭 运行向导」点击 |
| 初始屏 | 按 `wizardProgress.step` 恢复（无则屏 0） | 屏 1（跳过欢迎屏） |
| 预填 | 默认示例值（DeepSeek 等） | 当前实际配置（Provider 列表第一个 / 活动工作区） |
| 已有配置标记 | — | 每个已配置项显示 ✅ 徽标 + 「保留现有配置，下一步」快捷按钮 |
| 完成动作 | 置 `wizardCompleted=true` + 清 `wizardProgress` | 仅保存用户修改项，`wizardCompleted` 不动 |

### 4.2 进度落盘（新增小扩展）

- 复用 `POST /api/settings/section`：`{ section: 'wizardProgress', data: { mode: 'first-run' | 'guided', step: 1, providerSaved: true, workspaceSaved: false } }`；
- `checkBootstrap` 返回体附带 `wizardProgress`，前端据此定位初始屏（仅首启模式消费）；
- `wizardFinish()` 成功后置 `wizardCompleted=true` 并清空 `wizardProgress`（老键语义完全兼容）。

### 4.3 校验规则

| 步骤 | 校验 | 时机 |
| --- | --- | --- |
| 屏 1 → 2 | Provider 已保存（`wizardSaveProvider` 成功返回）或引导模式勾选「保留现有配置」 | 点击"保存并继续" |
| 屏 2 → 3 | 路径非空、`fs.existsSync && isDirectory`（走既有 `/api/directory-browse` 或轻量 exists 探测端点） | 输入时实时 + 点击时强校验 |
| 屏 3 → 工作台 | 两项均 ✅（首启）/ 至少确认过一遍（引导） | 点击"进入工作台" |

### 4.4 重跑入口（即引导模式入口）

- 顶栏 ⚙️ 设置下拉新增一项「🧭 运行向导」（引导模式）：**不弹确认**（无破坏性，预填现有配置，随时可退）→ 直接以 `mode: 'guided'` 打开向导；
- 引导模式中途退出（点遮罩外/ESC/跳过）仅关闭覆盖层，已填项不落盘、已存项不受影响；
- 既有配置在屏 1/2 预填当前值，用户可一路「保留现有配置，下一步」快速通过，也可改任意项。

## 5. 视觉规格

- 全屏遮罩 `bg-black/85 backdrop-blur-md`（沿用现有弹窗底），中央卡片 `max-w-2xl`，比现弹窗（max-w-lg）略宽以容纳价值卡片；
- 进度点：屏 0~3 对应 `● ● ● ●`，当前屏实心蓝、已完成实心绿、未到空心灰；**引导模式**（跳过屏 0）进度点显示为 `○ ● ● ●` 且屏 0 点隐藏；
- 价值卡片：三列 grid，图标 + 标题 + 一句话，hover 微亮（仅首启模式渲染）；
- 引导模式专属：已配置项的 ✅ 徽标（emerald）与「保留现有配置，下一步」按钮（slate 次级样式，与主按钮区分）；
- "为什么需要"提示：`ℹ️` 蓝色左边框说明条，可折叠（默认展开）；
- 主题：全部沿用现有 CSS 变量与 Tailwind 类，明亮模式自动生效（新增色类需过 theme-light 测试）。

## 6. 兼容与降级

- 老 `wizardCompleted=true` 的存量用户**首启模式永不自动弹出**（行为不变）；引导模式随时可用；
- `wizardProgress` 字段缺失（老数据）→ 首启从屏 0 开始；
- 后端无需新端点（复用 settings section 机制），仅需 `needsWizard` 响应附带 `wizardProgress`（一处小改）；
- 向导内任何保存失败：屏内红字提示，不阻塞返回上一步；
- 引导模式边界：工作区/Provider 均已配置时，屏 1/2 表单预填后「保存并继续」等价于「确认无修改」——不做空判断阻断（引导模式允许零修改走完全程）。

## 7. 测试计划

- `wizard-v2.test.ts`（结构断言，沿用 topbar 测试模式）：
  1. 全屏向导容器与四屏 DOM 存在；旧 `#wizard-modal` 移除；
  2. 进度点四枚；屏 0 含价值卡片 ×3 与"跳过"入口；
  3. 屏 1/2 保留现有 input id（wizard-provider-key 等，确保既有 wizard 函数不破坏）；
  4. `wizardProgress` section 读写调用存在且含 `mode` 字段；设置菜单存在「🧭 运行向导」入口（引导模式）；
  5. 屏 2 实时校验函数存在；完成页含"加更多模型/工作区"指引文案；
  6. 引导模式专属：`startWizard(mode)` 双模式入口、预填逻辑、「保留现有配置」快捷按钮存在。
- 既有 `bootstrap.test.ts` / `sprint3-*` 回归必须全绿（`needsWizard` 语义不变）。
- CDP 端到端：
  - 首启模式：全新 data-dir 启动 → 向导自动出现 → 走完四屏 → 进入工作台 → 中途刷新断点续走；
  - 引导模式：已有配置会话 → 设置菜单点「🧭 运行向导」→ 直接进屏 1 且表单预填现有 Provider → 「保留现有配置」一路通过 → 已存配置无任何变化。

## 8. 不做（YAGNI）

- 多语言切换；向导内嵌视频/动画；MCP/Skills 配置步骤（已有独立页面，向导只做最小可用闭环）；步骤多于四屏；引导模式下的多 Provider/多工作区批量管理（各自有专门页面，向导只引导"第一个/当前激活项"）。
