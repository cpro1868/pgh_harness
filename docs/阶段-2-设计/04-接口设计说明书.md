## 1. 接口设计规范与网络边界

Harness 服务端基于 Fastify 构建，提供高性能的 RESTful 数据接口与标准 Server-Sent Events (SSE) 事件流通道。

### 1.1 网络环境与安全认证规范
- **本地回环监听 (`127.0.0.1`)**：默认模式，免密访问，开箱即用；
- **网络暴露监听 (`0.0.0.0`)**：当服务端配置为监听局域网或公网时，强制要求环境变量包含 `HARNESS_ACCESS_TOKEN`，否则拒绝启动；此时所有客户端发起的请求，必须在 HTTP Request Header 中携带身份令牌：
  ```http
  Authorization: Bearer <HARNESS_ACCESS_TOKEN>
  ```
  未提供或校验不匹配统一返回 `401 Unauthorized`。

### 1.2 数据交互格式规范
- **请求格式**：`Content-Type: application/json; charset=utf-8`；
- **常规响应格式**：`Content-Type: application/json; charset=utf-8`，标准包络如下：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": {}
  }
  ```
- **流式推送格式**：`Content-Type: text/event-stream; charset=utf-8`，长连接心跳保持，无缓冲实时推送。

## 2. 会话管理接口集合 (Sessions API)

### 2.1 创建新会话
- **请求路径**：`POST /api/sessions`
- **功能描述**：根据用户选择的工作区路径与安全预设，创建新会话并物理锁定工作区。
- **请求参数 (JSON Body)**：
  | 字段名 | 类型 | 必填 | 说明 |
  | :--- | :--- | :--- | :--- |
  | `workspacePath` | string | 是 | 绑定的工作区物理绝对路径 |
  | `preset` | string | 否 | 权限安全预设：`readonly` / `edit` (默认) / `full` |
  | `modelId` | string | 否 | 指定使用的模型 ID，留空使用全局默认模型 |
  | `title` | string | 否 | 初始会话标题 |
- **响应示例 (`201 Created`)**：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": {
      "sessionId": "sess_89f2a4",
      "workspacePath": "G:\\Projects\\auth-service",
      "preset": "edit",
      "activeModelId": "deepseek-chat",
      "createdAt": 1789721000000
    }
  }
  ```

### 2.2 获取会话列表
- **请求路径**：`GET /api/sessions`
- **功能描述**：分页获取历史会话概览列表，按更新时间倒序排序。
- **Query 参数**：`limit` (整数，默认 20)，`offset` (整数，默认 0)。
- **响应示例 (`200 OK`)**：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": {
      "total": 15,
      "items": [
        {
          "id": "sess_89f2a4",
          "title": "修复 auth/token 边界溢出 bug 并补全单测",
          "workspacePath": "G:\\Projects\\auth-service",
          "preset": "edit",
          "activeModelId": "deepseek-chat",
          "updatedAt": 1789721600000
        }
      ]
    }
  }
  ```

### 2.3 获取会话物化消息流 (全量/增量)
- **请求路径**：`GET /api/sessions/:id/messages`
- **功能描述**：拉取指定会话由事件流物化还原的完整消息与工具卡片树。
- **Query 参数**：`afterSeq` (可选，整数。若传入，仅返回 `seq > afterSeq` 的增量新消息)。

## 3. 回合交互与 SSE 流式推送接口 (Turns & Stream API)

### 3.1 投递消息并开启流式推送
- **请求路径**：`POST /api/sessions/:id/messages`
- **功能描述**：向指定会话发送用户需求指令，服务端立即挂起建立 SSE 流式通道，实时推送思考链、文字增量、工具调用及阶段完成状态。
- **请求参数 (JSON Body)**：
  | 字段名 | 类型 | 必填 | 说明 |
  | :--- | :--- | :--- | :--- |
  | `content` | string | 是 | 用户指令正文 |
  | `enableSubagents`| boolean| 否 | 是否允许当前回合派发子智能体 (Subagents) |
- **SSE 事件帧格式规范**：
  每个数据帧均附带单调递增的全局 `seq` 序号与事件类型：
  ```
  id: 101
  event: stream/chunk
  data: {"seq":101,"turnId":"turn_01","type":"reasoning","chunk":"正在定位溢出根因..."}

  id: 102
  event: tool/call
  data: {"seq":102,"turnId":"turn_01","callId":"call_01","tool":"read_file","args":{"filePath":"src/auth.ts"}}

  id: 103
  event: tool/result
  data: {"seq":103,"turnId":"turn_01","callId":"call_01","output":"function verifyToken(amount: number)..."}

  id: 104
  event: turn/completed
  data: {"seq":104,"turnId":"turn_01","durationMs":3200,"tokens":{"input":3500,"output":240}}
  ```

### 3.2 断线重连无缝续传与 15s 心跳端点 (D69)
- **请求路径**：`GET /api/sessions/:id/stream`
- **功能描述**：
  - 当客户端网络波动、浏览器休眠切回或刷新页面时，传入最后收到的事件编号，服务端自动补齐断点期间丢失的全部帧并继续推流；
  - **15s 心跳保活机制**：服务端常驻每隔 15 秒向客户端下发 `: ping\n\n` 空注释心跳帧；客户端通过 `visibilitychange` 与 30 秒静默感知半开死链接，秒级重新调用本端点补发拉齐。
- **Query 参数**：`after` (可选，整数，客户端持有的最新 `seq` 编号。若缺省则仅监听新帧)。

### 3.3 显式打断终止 (Abort)
- **请求路径**：`POST /api/sessions/:id/abort`
- **功能描述**：干净硬杀。立即中断正在进行的 LLM HTTP 流，向正在执行的 Shell/测试子进程树调用 `taskkill /pid /T /F`（Windows）或负进程组信号（Unix），已产出内容正常入库并标记为 `aborted`。
- **响应示例 (`200 OK`)**：
  ```json
  { "code": 0, "message": "session aborted successfully" }
  ```

### 3.4 单回合 Git 变更原子撤销 (Revert Turn - D59)
- **请求路径**：`POST /api/sessions/:id/revert-turn`
- **功能描述**：基于回合前建立的 Checkpoint 快照，一键撤销本回合涉及的所有代码修改，原子恢复至回合开始前的干净基线，杜绝误伤开发者原有的未提交手写代码。
- **响应示例 (`200 OK`)**：
  ```json
  { "code": 0, "message": "turn changes reverted successfully", "revertedFiles": ["src/token.ts"] }
  ```

### 3.5 从流式断点继续生成 (Continue from Interrupted)
- **请求路径**：`POST /api/sessions/:id/continue`
- **功能描述**：当上一轮流式传输遭遇意外断网中途截断时，以已生成的半截内容为前缀基底，向模型发起补充提示继续补完剩余代码，无需整轮重跑。
- **响应示例 (`200 OK`)**：建立新的 SSE 连接并继续输出剩余分片。

### 3.6 工作区互斥写锁检测、租约让渡与抢占打断 (D42, D64)
- **请求路径**：`GET /api/workspaces/lock-status?workspacePath=...` 与 `POST /api/workspaces/preempt`
- **功能描述**：
  - 查询指定工作区当前是否有其他会话正在持有物理写锁；
  - 支持查看多智能体任务中的父子写锁租约流转状态（Parent-Child Delegation）；
  - 在冲突时支持由人类确认下发强制中断并由当前会话接管写锁。

### 3.7 人机澄清提问回答与驳回端点 (QuestionV2 - D53, Q8)
- **回答提问**：`POST /api/questions/:requestID/reply`
  - **请求参数**：`{ "answers": [["option_a"]] }`
  - **功能**：解除提问挂起状态，将人类选中的选项作为工具输出回灌调度器继续执行。
- **驳回提问**：`POST /api/questions/:requestID/reject`
  - **功能**：开发者关闭或驳回提问弹窗，抛出 `RejectedError`，模型得知人类跳过提问自行决断。

### 3.8 人工高危审批裁决
- **请求路径**：`POST /api/sessions/:id/approvals/:callId`
- **功能描述**：当操作命中安全规则进入等待审批时，提交人类放行或拒绝决定。
- **请求参数 (JSON Body)**：
  | 字段名 | 类型 | 必填 | 说明 |
  | :--- | :--- | :--- | :--- |
  | `decision` | string | 是 | 决策：`approved` (批准单次) / `allow_always` (本会话始终允许) / `rejected` (拒绝) |
  | `reason` | string | 否 | 拒绝理由或人类补充意见反馈 |

## 4. 记忆与经验治理接口 (Memory Governance API)

### 4.1 查询工作区记忆配置与概览
- **请求路径**：`GET /api/memories/config`
- **Query 参数**：`workspacePath` (工作区路径)。
- **响应示例 (`200 OK`)**：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": {
      "workspacePath": "G:\\Projects\\auth-service",
      "storageMode": "file",
      "extractionMode": "auto",
      "markdownPath": ".harness/memory.md",
      "totalEntries": 5,
      "pendingReviewCount": 0
    }
  }
  ```

### 4.2 存储模式受控变更与数据迁移向导
- **请求路径**：`POST /api/memories/migrate`
- **功能描述**：执行受控存储模式切换，支持全新起步丢弃测试数据或原子事务数据无损迁移。
- **请求参数 (JSON Body)**：
  ```json
  {
    "workspacePath": "G:\\Projects\\auth-service",
    "targetMode": "sqlite",
    "targetParams": {
      "sqlitePath": ".harness/project-memory.sqlite",
      "tableName": "tbl_mem_auth",
      "fts5Enabled": true
    },
    "policy": "migrate"
  }
  ```
- **参数说明**：
  - `policy`: `fresh`（全新起步，丢弃测试数据，原文件自动 `.bak` 归档）或 `migrate`（平滑数据迁移，SHA-256 自动去重）。
- **响应示例 (`200 OK`)**：
  ```json
  {
    "code": 0,
    "message": "migration completed successfully",
    "data": {
      "migratedCount": 5,
      "backupFile": "G:\\Projects\\auth-service\\.harness\\memory.md.20260918.bak"
    }
  }
  ```

## 5. 通用 Skills 技能包管理接口 (Skills API)

### 5.1 扫描并获取可用技能清单
- **请求路径**：`GET /api/skills`
- **Query 参数**：`workspacePath` (当前工作区路径)。
- **功能描述**：以渐进披露模式返回当前可用的技能元数据（仅包含 `name`、`description` 等），不携带庞大正文。
- **响应示例 (`200 OK`)**：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": [
      {
        "name": "systematic-debugging",
        "description": "Use when encountering any bug, test failure, or unexpected behavior...",
        "version": "1.2.0",
        "sourceLevel": "project",
        "packagePath": ".agents/skills/systematic-debugging",
        "enabled": true
      }
    ]
  }
  ```

### 5.2 导入本地原子 Skill 包
- **请求路径**：`POST /api/skills/import-local`
- **功能描述**：校验本地 Skill 目录合法性（检查是否存在合规包含 YAML Front-matter 的 `SKILL.md`），执行拷贝或软链导入。
- **请求参数 (JSON Body)**：
  | 字段名 | 类型 | 必填 | 说明 |
  | :--- | :--- | :--- | :--- |
  | `sourcePath` | string | 是 | 本地技能包绝对路径目录 |
  | `targetLevel`| string | 是 | 导入目标层级：`project` (当前项目) / `global` (全局) |
  | `importMode` | string | 否 | 导入方式：`copy` (默认，完整文件复制) / `symlink` (创建软链) |

## 6. 系统设置、网络代理与 Provider 探测接口 (System API)

### 6.1 全局网络代理获取与保存 (D60)
- **获取配置**：`GET /api/settings/proxy`
- **保存配置**：`PUT /api/settings/proxy`
  - **请求参数**：包含启用开关、协议（`HTTP`/`HTTPS`/`SOCKS5`）、Host、Port、用户名/密码与 Bypass 绕过名单。

### 6.2 动态获取 Provider 可用模型清单 (支持双轨协议与独立代理)
- **请求路径**：`POST /api/providers/models`
- **功能描述**：根据传入的 BaseURL、API Key、接口协议类型（`openai-compatible` / `anthropic-native`）以及 Provider 专属代理设置，向对应端点发起探测，解析并返回清洗后的可用模型清单。
- **请求参数 (JSON Body)**：
  ```json
  {
    "protocol": "openai-compatible",
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "sk-***",
    "proxy": {
      "enabled": true,
      "mode": "inherit"
    }
  }
  ```
- **响应示例 (`200 OK`)**：
  ```json
  {
    "code": 0,
    "message": "success",
    "data": {
      "models": [
        { "id": "deepseek-chat", "name": "DeepSeek-V3", "contextWindow": 65536 },
        { "id": "deepseek-reasoner", "name": "DeepSeek-R1 (推理)", "contextWindow": 65536 }
      ]
    }
  }
  ```

### 6.3 查询与保存系统全局设置
- **请求路径**：`GET /api/settings` 与 `PUT /api/settings`
- **功能描述**：管理服务端口、Token 口令、主题配色方案与系统全局持久化数据目录。

### 6.4 首次运行一键破冰向导提交 (Setup Wizard API - D57)
- **请求路径**：`POST /api/setup/quick-init`
- **功能描述**：新安装系统首次启动时，一次性写入初始 Provider 配置并创建首个工作区任务会话。
- **请求参数 (JSON Body)**：
  ```json
  {
    "provider": {
      "baseUrl": "https://api.deepseek.com/v1",
      "apiKey": "sk-dsh89f2a4..."
    },
    "workspacePath": "G:\\Projects\\auth-service"
  }
  ```
- **响应示例 (`201 Created`)**：返回新建的 `sessionId` 并引导直接进入主对话。
