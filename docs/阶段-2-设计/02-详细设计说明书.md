## 1. 会话管理与人机交互分块详细设计 (MOD-01)

### 1.1 业务模型与状态迁移
每个会话是独立的上下文执行单元，包含以下生命周期状态：
- `idle` (空闲)：等待用户输入，所有数据完全持久化；
- `running` (执行中)：Agent 正在调用 LLM 或运行本地工具，前端输入框锁定，显示 Abort 按钮；
- `waiting_approval` (挂起待审批)：命中敏感操作拦截规则，等待人工放行；
- `suspended` (异常挂起)：遭遇 429 或网络重试耗尽，保留上下文引导用户切换模型或重试；
- `aborted` (已中断)：用户主动点击打断终止。

### 1.2 物理工作区绑定与读写锁互斥契约 (D42, D43)
- **锁定机制**：创建会话时传入绝对路径 `workspacePath`。服务端校验目录有效性后，在会话生命周期内将该路径置为**只读常驻属性**；
- **防越界防卫**：所有后续会话内部引发的文件读写、代码搜索，必须被严格校验在 `workspacePath` 根目录之内，传入 `../../` 相对路径立即报越界拒绝。
- **并发控制：读共享 / 写互斥**：
  - 同一物理工作区允许多个历史会话存在；
  - 纯只读操作（搜索、阅读代码）完全放行共享；
  - 物理写操作（改写代码、执行构建或测试）实施严格互斥独占写锁。若会话 B 触发写操作时会话 A 正持有写锁，调度层原生挂起会话 B，前端顶部给出倒计时等待提示条，并提供人类一键【中断会话 A 并接管】操作。

### 1.3 首次启动极简就绪向导 (First-Run Wizard - D57)
- 当系统检测到初次启动或数据空状态时，前端弹出轻量两步就绪向导：
  1. 步骤 1：填入首个 Provider API Key 与 BaseURL 并测试连通；
  2. 步骤 2：点选首个本地工作区目录；
  完成后直接开启首个任务会话破冰，免去用户在复杂配置页来回迷茫。

## 2. 智能体循环调度分块详细设计 (MOD-02)

### 2.1 ReAct 调度核心大循环
调度器负责执行确定性的单回合状态机（Turn Loop）：
1. **组装阶段**：收集用户输入、工作区规则文件、上下文历史，并调用记忆引擎按任务文本召回 Top-K 历史经验；
2. **快照锁定**：触发生成 `request/context` 事件入库，确保该步模型看到的内容 100% 可回溯；
3. **推理阶段**：发起 LLM 请求，解析 SSE 流。遇到模型输出普通文字，累加输出；遇到 `tool_calls`，结束本步推理，生成结构化调用参数；
4. **工具派发**：将工具与参数投递至安全权限层（MOD-05），通过后调用本地工具（MOD-04）；
5. **结果回灌**：工具产出经过上下文截断治理后作为 `tool` 角色消息追加，步序计数 `stepIndex++`，循环进入下一轮推理；
6. **终止收敛**：当模型不再调用工具输出最终解答、步数达到安全阈值（默认 25 步）、或用户触发 Abort 时，退出循环，触发记忆反思与会话事件落盘。

### 2.2 跨平台进程树硬杀打断机制 (Abort Protocol - 吸收 OpenCode/pi 经验)
用户点击打断后，调度器执行三级联动硬杀：
1. **网络层**：立即调用 LLM HTTP 连接的 `AbortController.abort()`，中断流式接收；
2. **进程层（跨平台进程树终结）**：
   - **Windows 平台**：针对 Windows 原生不支持 POSIX 信号且 `child_process.kill()` 无法连带清除衍生子进程的问题，统一调用系统级 `taskkill /pid <PID> /T /F`，强制终结包括 Shell、测试运行器（如 Jest/Vite）及编译器在内的整棵子孙进程树，彻底杜绝孤儿僵尸进程占用文件锁与端口；
   - **POSIX (Linux/macOS) 平台**：采用进程组机制派生子进程，通过对负进程组 ID 发送 `process.kill(-pgid, 'SIGKILL')` 彻底杀死整组进程；
3. **状态层**：将当前未完成的回合状态标记为 `aborted`，保留已输出的全部消息与工具日志，允许开发者在此基础上原地发送新指令继续。

### 2.3 单回合 Git 状态检查点与原子回滚 (Revert Turn - D59)
- **检查点建立 (Checkpoint)**：
  - 在任何包含代码物理修改或测试运行的回合开始前，调度层轻量捕获工作区 Git 脏状态快照；
  - **用户手写修改隔离保护 (Q1)**：若检测到工作区在回合开始前已存在用户未提交的手写代码，底层自动执行临时快照（Stash/Patch）保护；
- **原子撤销恢复**：
  - 若模型陷入错误修复死循环、导致构建失败或开发者对手改结果不满意，点击【撤销本回合修改 (Revert Turn)】；
  - 调度层自动执行原子化还原：针对本回合修改的文件执行精确还原，新创建的文件执行 `git clean -fd` 清理，坚决不冲掉用户原有的未提交手写基线；
- **快照生命周期管理 (Q4)**：
  - Checkpoint 严格定位为“当前活动回合的即时后悔药”；
  - 用户开启新一轮交互或发送新指令时，前一回合的临时快照在后台自动静默销毁，绝不在本地 Git Stash 列表中残留垃圾。

## 3. 数据存储与持久化分块详细设计 (MOD-03)

### 3.1 物理存储介质与单实例锁防线 (D65)
- 基于 Node 22 原生内置 `node:sqlite`（`DatabaseSync`），配置 `PRAGMA journal_mode = WAL` 与 `PRAGMA synchronous = NORMAL`，保障高并发写入不锁库；
- 数据默认存放在用户主目录 `~/.harness/harness.db`，支持通过启动参数 `--data-dir` 自定义；
- **单实例文件锁防线 (Q6)**：启动时在 `~/.harness/.lock` 写入主进程 PID 与端口，若检测到并发实例运行立即安全阻断，提示用户现有端口或要求指定独立目录，从根源杜绝 `SQLITE_BUSY` 冲突。

### 3.2 追加式事件日志架构 (Event Sourcing)
系统严格废除“直接修改消息记录”的破坏性模式，所有历史皆由事件表 (`events`) 还原物化：
- 每条事件分配会话局部连续的 `seq` 整数序号；
- 通过事件重放（Replay），确定性计算出任意历史时刻的完整消息树与工具调用卡片；
- 支持 Fork 会话功能：指定历史某一 `seq` 序号即可拉出全新分支会话继续探索。

### 3.3 大输出溢出落盘机制与私有子目录隔离 (Spill Storage - D68)
当终端运行日志（如打印全部依赖包）或抓取的网页正文大于阈值（默认 50KB）时：
1. 提取内容计算 `SHA-256` 哈希指纹；
2. 将正文作为独立文件保存至会话专属私有子目录 `~/.harness/sessions/<sessionId>/blobs/<sha256>.txt`；
3. 在数据库事件流中仅记录指向该 Blob 的引用指针及截取的前 200 字摘要，防止数据库暴涨与模型上下文被无用垃圾信息瞬间挤爆；
4. **生命周期原子联动**：删除会话时，底层原子递归清空该会话的私有 blobs 目录，无全局死锁风险，零孤儿垃圾文件。

## 4. 核心执行与工具分块详细设计 (MOD-04)

### 4.1 核心编码工具集定义
- `read_file(filePath, offset?, limit?)`：读取文本文件，默认带行号前缀，支持窗口切片；
- `edit_file(filePath, oldString, newString, replaceAll?)`：精确字符串原子替换。必须执行前置校验（先读后写原则：未读过的文件禁止直接修改）；
- `write_file(filePath, content)`：创建新文件或覆盖写入；
- `glob(pattern)` 与 `grep(pattern, path?)`：工程级文件路径通配与正则关键词快速检索；
- `bash(command, timeout?, workdir?)`：执行操作系统命令，受工作区根目录与权限白名单约束；
- `ask_user(question, options?)`：结构化提问工具，渲染选项供人类点选，收集开发决策。

### 4.2 工具调用安全守卫与故障熔断机制
- **外部修改防写死 (D44)**：`edit_file` 执行修改前强制校验文件 mtime 或指纹哈希，若检测到已被外部人肉修改，坚决不盲目覆盖，自动重读最新内容提示模型刷新上下文；
- **局部修改失败熔断刹车 (D46)**：单文件连续 3 次发生匹配替换失败，调度层强制熔断，暂停重试向人类求援，彻底杜绝死循环空转烧 Token；
- **沙箱路径绝对校验 (D52)**：所有传入路径在执行前强制走 `fs.realpathSync` 物理反解，拦截符号链接 (Symlink) 穿越沙箱；
- **命令非交互与硬超时 (D45)**：`bash` 执行默认强制注入非交互环境变量（`CI=true` 等），单命令硬设 120 秒超时拦截，防范终端假死；
- **敏感输出脱敏兜底 (D48)**：命令输出在写入事件库与回灌模型前，底层通过正则自动过滤将发现的 API Key 或密码替换为 `[REDACTED]`；
- **人机提问异步等待与恢复 (D53, Q8)**：
  - 对齐 OpenCode `QuestionV2` 标准，每次提问生成独立的 `que_<uuid>` 标识符；
  - 暴露 `POST /api/questions/:id/reply`（回答）与 `POST /api/questions/:id/reject`（驳回）双轨端点；
  - 客户端休眠断线重连时，调度层从数据库事件中精准重新物化未决提问卡片，等待人类交互；
- **MCP 工具命名空间隔离 (D66, Q9)**：
  - 外部 MCP 服务注册的工具强制附加 `mcp__<server>__<tool>` 命名空间前缀；
  - 本地 6 大核心编码工具名称作为保留字独占，从协议根源防止沙箱工具被劣质/恶意 MCP 劫持。

### 4.3 持久 Shell 运行管道与 Windows 深度适配 (Persistent Terminal Pipeline - Q2)
- 依靠 `node:child_process.spawn` 启动宿主系统的命令行解释器：
  - **Windows 探测降级链**：优先探测 `pwsh.exe`，降级至 `powershell.exe`，最终降级至 `cmd.exe`；
  - **组策略权限绕过**：针对 PowerShell 强制附加 `-NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass` 参数，彻底杜绝企业环境下脚本执行受限报错；
  - **POSIX 平台**：优先探测 `$SHELL` 或 `/bin/bash`，降级至 `/bin/sh`；
- 保持单个会话内的进程持久化，用户前一条命令设置的环境变量或 `cd` 路径在下一条命令依然生效；
- 支持挂载长驻后台任务（如 `npm run dev`），并在前端实时捕获标准增量输出。

## 5. 权限拦截与安全防线分块详细设计 (MOD-05)

### 5.1 规则拦截决策流水线 (Deny > Ask > Allow)
每次工具执行前，安全检查器依次求值：
1. **Deny 规则匹配**：命中黑名单（如尝试修改 `.git` 内部文件、读取宿主环境变量私钥文件）立即报错并拒绝执行；
2. **Ask 审批规则匹配**：命中高危动作（执行可能具有破坏性的 Shell 脚本如 `rm -rf`、跨目录修改关键配置）进入挂起态，向用户抛出审批请求；
3. **Allow 规则匹配 / 预设策略求值**：命中白名单或处于全权模式下，方可真正触发操作系统执行。

### 5.2 安全审批门 (Human-in-the-Loop Approval)
- 前端拦截后展示高保真审批弹窗；
- 若涉及代码修改，自动生成红绿对照的统一 **Diff 视窗**；若涉及命令执行，完整呈现具体命令脚本与执行目录；
- 人类操作选项清晰支持：**「单次批准放行」**、**「本会话始终允许该动作」** 与 **「直接拒绝并附带反馈」**。

## 6. 上下文治理与计量分块详细设计 (MOD-06)

### 6.1 Token 分层精细化计量与思考模型治理 (D58)
- **请求前预估**：在将上下文推给大模型之前，通过分词字符近似估算本次输入消耗，若发现超限提前阻止；
- **回包后校正**：接收到模型返回的官方 `usage` 统计字段后，精准校正入库，并归入统计分类（如正常对话消耗、上下文压缩消耗）；
- **思考模型 (Reasoning Token) 协议隔离与治理**：
  - 针对 DeepSeek-R1、Claude 3.7 Sonnet 等具有深度推理特性的模型，独立提取 `reasoning_content`，入库为独立的 `reasoning` 事件帧；
  - 数据库独立计量 `tokens_reasoning` 指标；
  - **历史回合上下文剥离策略**：在单回合内实时向前端渲染思考链；但在回合结束组装下一轮历史上下文（`deriveMessages`）时，**默认自动剥离/剪枝历史思考块**，仅持久化在底层 SQLite 供人类复盘审计，杜绝上下文被海量思维链过早撑爆；
- **费用实时换算**：根据当前模型登记的百万 Token 单价，在前端顶栏实时跳动展示当前会话花费金额（如 `$0.024`）。

### 6.2 基于 Epoch/Seq 边界的无上限滚动压缩 (Compaction - D50, Q7)
- **机制升级（对齐 OpenCode）**：废除固定的压缩次数死限，系统支持根据任务复杂度无上限滚动压缩；
- **历史切片基线锁定**：
  - 每次压缩产生一个类型为 `compaction` 的事件帧入库；
  - 历史消息物化重构时，直接以最新 `compaction.seq` 作为活跃历史起始边界，前序海量旧事件不再参与组装，仅保留压缩摘要卡片；
- **滚动摘要链与尾部保留 (Tail Turns)**：
  - 发生多轮压缩时，将前序摘要与新增溢出内容平滑合并，同时铁律保护最近 3 轮（或保留 token 预算内）的核心交互与未完成工具调用原样不压缩；
- **溢出紧急自动恢复 (`compactAfterOverflow`)**：
  - 若模型意外抛出 `context_length_exceeded` 物理硬报错，调度器捕获后自动紧急执行就地压缩，并原地无缝重新发起请求，保障长任务永不因溢出报错中断。

### 6.3 全局与项目双层记忆装配 (Memory Hierarchical Loading - D67, Q10)
- **双层装配拓扑（对齐 OpenCode `instruction-context.ts`）**：
  1. **系统全局层**：读取 `~/.harness/AGENTS.md` 或全局记忆规约，提供跨项目通用的个人偏好；
  2. **项目专属层**：沿工作区目录向上回溯探测 `<workspace>/AGENTS.md`，提供当前仓库专属的架构准则与编码规范；
- **级联注入与去重**：
  - 组装 System Prompt 时，按固定前缀显式标注来源路径并执行去重合并；
  - 既保障多项目间的架构规范互不污染，又免除开发者跨项目重复调教个人习惯的痛点。

## 7. 基础模型与生态接入分块详细设计 (MOD-07)

### 7.1 统一双轨协议接入与物理上下文窗口动态感知 (D51, D61)
- 建立统一的 `ModelProvider` 抽象 Seam，原生支持两大主流事实协议：
  - **OpenAI Compatible 模式**：适配 DeepSeek、通义千问、OpenRouter、本地 Ollama 等标准 `/v1/chat/completions` 端点；
  - **Anthropic Native 模式**：适配 Claude 官方 `/v1/messages` 端点，深度支持提示词缓存 (Prompt Caching) 与原生思考块 (Thinking Block)，避免兼容协议转译损耗；
- **模型自动发现机制**：在配置页面填入 Provider 的 BaseURL 与 API Key 后，提供独立的【获取模型列表 (GET /models)】按钮，现场握手探测并将后端返回的模型 ID 自动清洗填充进前端选择下拉框；
- **物理窗口动态感知与覆盖**：前端展示各模型的实际物理窗口（如 16k/64k/128k/192k/200k），允许用户自由调大或调小，系统压缩警戒水位线严格绑定生效物理窗口的 80%；
- 运行态模型即时热切换：在对话中途支持通过顶栏微型选择器随时无损切换模型底座。
- **MCP 外部服务隔离 (D55)**：MCP 服务连接失败或单次超时（15秒）自动降级隔离，不影响核心本地文件与执行工具。

### 7.2 两级网络代理分流调度架构 (Global & Provider Proxy - D60)
为彻底解决开发者访问海外商用 LLM 与本地/内网私有服务的网络分流冲突，网络层提供两级代理调度机制：
- **两级配置体系**：
  1. **全局系统代理 (Global Proxy)**：在系统设置中配置并开启，影响全系统外部网络流量；
  2. **Provider 专属代理 (LLM Proxy)**：在 Provider 配置中提供「强制直连」、「继承全局代理」与「独立自定义代理」三级模式；
- **端点卡片独立开关**：在已配置 Provider 资产列表中常驻独立 Toggle 开关，排查网络故障时支持秒级切换直连与代理；
- **核心配置要素**：支持协议（`HTTP` / `HTTPS` / `SOCKS5`）、服务器地址、端口、可选账号/密码掩码认证；
- **白名单强制直连保障**：支持注入 `NO_PROXY` 绕过名单（默认排除 `localhost, 127.0.0.1, ::1, *.local`），杜绝本地 Vite/SQLite/Ollama 被错误转发至代理服务器引发连接死锁；
- **底层实现技术**：在 Node 22 运行时中基于 `undici.EnvHttpProxyAgent` 动态路由，兼具轻量高效与零 Native 依赖。

### 7.3 通用 Agent Skills 规范管理
- **文件规范**：严格遵循行业事实标准的 **YAML Front-matter + Markdown** 契约，每个技能独立为包含 `SKILL.md` 的原子目录；
- **多层级发现优先级**：优先扫描工作区目录 `<workspace>/.agents/skills/` 与 `.skills/`，向后兼容 `.harness/skills/`，统一全局目录 `~/.config/agents/skills/`；
- **渐进披露机制**：冷态阶段仅提取 YAML 头的 `name` 和 `description` 组合进 System Prompt，模型命中意图后自主调用 `skill(name)` 工具，热态加载正文，实现零上下文负担。

## 8. 服务端通信与网关分块详细设计 (MOD-08)

### 8.1 RESTful API 契约
- 负责会话的增删改查、历史消息物化拉取、审批决策回传与本地配置更新。

### 8.2 Server-Sent Events (SSE) 流式传输规范与休眠重连 (D69)
- 服务端建立常驻事件管道，每一帧事件均包含单调递增的 `seq` 编号；
- **双向心跳保活 (Ping-Pong)**：服务端每隔 15 秒向长连接推送 `: ping\n\n` 心跳包；
- **页面可见性感知与息屏假死重连**：
  - 客户端监听 `document.visibilitychange`；若页面从后台恢复或连续 30 秒未收到任何心跳帧，立即主动判定连接已死，关闭当前连接；
  - 自动携带最新序号 `GET /api/sessions/:id/stream?after=<seq>` 发起增量重连，瞬间补齐休眠断网期间产生的全部事件；
- **流式截断断点保护 (D47)**：若流式传输中途因网络被掐断，系统将已生成的半截文字或思考作为真实事实写入事件库落盘，前端呈现明确断点提示，并提供【从断点继续】与【整轮重新生成】按钮。

### 8.3 网络监听、口令防护与静默僵死熔断 (D63)
- 系统启动时默认监听 `127.0.0.1` 本地回环地址，无需强制口令；
- 当开发者显式配置监听 `0.0.0.0` 或暴露于局域网/公网时，服务端强制拦截校验环境变量 `HARNESS_ACCESS_TOKEN`，未设置则拒绝启动，外网所有请求必须携带 Bearer Token 方可放行；
- **代理网络僵死硬超时熔断 (Q3)**：若请求经由代理发送，设置首包 30 秒、数据块静默 45 秒硬超时拦截，超时自动挂起为 `suspended` 并通知用户排查代理，严禁静默降级直连。

## 9. 多智能体协同与业务流分块详细设计 (MOD-09)

### 9.1 模式 B：会话级子任务委派与写锁让渡 (Subagents - D64)
- 在对话工作台输入框底部常驻「开启子任务委派」开关；
- 开启后当前会话注入内置 `spawn_agent` 工具能力；
- 子 Agent 拥有独立的任务定义、独立的临时单轮步数上限与预算控制，执行完毕后将产物精炼汇总回传主会话，不污染主会话长程消息流；
- **写锁租约继承与让渡模型 (Parent-Child Lock Delegation - Q5)**：
  - 子 Agent 继承父会话的工作区写锁租约（锁持有者绑定 `rootSessionId`）；
  - 子 Agent 执行期间父会话挂起；子 Agent 执行完成释放后原路返还写锁，彻底消解父子死锁，坚决守住工作区单实例独占修改底线。

### 9.2 模式 A：多角色协同流水线 (Role Pipeline)
- 围绕软件研发生命周期固化为阶段式泳道：`需求分析 PRD` &rarr; `架构设计` &rarr; `TDD 编码` &rarr; `QA 验收`；
- 每个阶段可指派不同角色的专用 Agent，配置不同的提示词与推荐模型；
- 具备严格的 **阶段审批门 (Gatekeeper)** 与工件契约流转协议；工件输出目录支持配置自定义输出路径，留空则自动按 Git 增量追踪变动代码；
- **上游审定工件只读保护 (D54)**：上游阶段经人类审批门放行后的交付工件，在下游角色执行时强制设为只读，严禁下游篡改上游基线；
- **版本控制安全红线 (D56)**：任务完成后 Agent 仅生成提交信息草稿供人类预览，`git commit` 需人类审批，严禁 Agent 自主静默执行 `git push`；
- 提供独立任务工作台 (`run-pipeline-detail.html`)，集成显式工作区绝对路径锁定与人机协同指令流窗口。

### 9.3 模式 C：BPMN 2.0 业务工作流引擎 (Workflow Engine)
- **标准资产**：原生解析与流转标准 BPMN 2.0 XML 模型，管理活动实例状态机；
- **现代可视化拖拽设计器 (`config-workflow-design.html`)**：
  - 左侧物料面板 (Node Palette)：支持事件、ServiceTask、人工放行、排他网关拖拽，支持一键折叠为极窄收纳条；
  - 中央无限点阵画布：双侧面板折叠后拥有 100% 满屏全景视野，支持贝塞尔连线与流转箭头渲染；
  - 右侧参数检查器 (Inspector Drawer)：点击任意节点平滑滑出，支持上游输入变量消费映射、双轨 Prompt 设定、全局变量总线输出映射与排他网关表达式在线求值沙盒；
- **实例追踪与动态可视化 (`run-workflow-detail.html`)**：具备动态高亮 SVG 拓扑大图、变量总线审计与人工干预指令流。

## 10. 记忆与经验治理分块详细设计 (MOD-10)

### 10.1 模式对比与生命周期解耦 (D49)
- **全自动模式**：任务或会话顺利结束时，后台静默调度轻量反思模型提炼踩坑规约直接入库，零打扰；
- **半自动审核模式**：提炼的经验条目先进入待审核队列，由工程师在控制台中直观对比原文与提取项后勾选批准，防止模型幻觉污染认知；
- **与会话压缩严格解耦**：中间过程触发的滑动窗口压缩仅用于释放当前对话空间，绝不向长期记忆库写入半成品经验；反思沉淀严格保留在任务/会话圆满终局时刻触发。

### 10.2 四大存储形态支持（按工作区独立配置）
1. ⚪ **未启用记忆 (Disabled)**：完全不反思、不记录、不注入，适用于保密沙箱或临时脚本；
2. 📄 **纯 Markdown 文件模式**：落盘于 `.harness/memory.md`，人类直观可读可改，随代码库一同 Git 提交协同；
3. 🔵 **本地嵌入式 SQLite 模式**：基于 Node 原生 `node:sqlite`（零 Native），支持自定义相对或绝对路径，集成 FTS5 全文索引实现毫秒级关键词检索；
4. 🟣 **Markdown 文件 + 向量双轨模式**：以 `.harness/memory.md` 为真相源，同时挂载本地 Embedding 模型计算切片向量，兼备版本化管理与语义联想切片召回。

### 10.3 存储介质受控变更与数据迁移向导
主界面工作区存储卡片采用**只读详情态锁定**，杜绝随意切换破坏数据。点击【变更存储模式与迁移...】呼出向导，动态展开新模式专属参数配置，并提供两极诉求精准分流：
- **诉求 A：全新起步，丢弃测试数据**：适用于初期调试验证，不执行迁移直接新建空白存储，原文件自动更名为 `.bak` 归档备份；
- **诉求 B：平滑数据无损迁移**：适用于生产项目积累，在原子事务中全量解析并按 SHA-256 内容指纹去重写入，确保历史经验无缝传承。
