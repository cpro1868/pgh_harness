PRD：在线支付校验模块

版本：v0.1（Agent 从 8 条讨论记录 + 8 个任务中提炼） · 状态：待确认 · 项目文件夹：docs/projects/payment-module/

1. 背景

中小团队（5-20 人）需要轻量级支付校验能力。Agent 通过与用户的自由讨论明确了以下要点：这是一个工具函数库（非完整支付流程），支持三种支付方式的合法性校验与差异化手续费计算。

2. 目标用户

  • 中小团队后端开发者（5-20 人），需快速集成支付校验

3. 核心功能（来源：讨论任务清单）

功能描述优先级讨论来源
支付方式校验card / paypal / bank_transfer 白名单机制P0讨论：支付方式范围确认
手续费计算card 2.9%，其他 0%；内部以分计算避免浮点精度问题P0讨论：费率表附件
元↔分转换层精度安全的金额转换（0.1+0.2 浮点问题规避）P0Agent 自动识别任务点
金额边界NaN/Infinity/负数/超 100 万拒绝（不截断）P0讨论：超上限策略确认
错误码体系invalid_method / unsupported_method / invalid_amountP1Agent 提炼
全额退款标记标记已退款状态（部分退款→二期）P1用户主动提出 + Agent 识别

4. 非功能需求

  • 零外部依赖（纯 Node.js 标准库）
  • 单元测试覆盖率 ≥ 90%
  • 单次校验 < 1ms（纯计算无 IO）

5. 验收标准

  • P0 功能全部有单元测试且通过
  • 边界用例：空值 / NaN / 负数 / 超大金额 / 非法字符串 / 原型链属性名
  • REVIEW.md / FIX-REPORT.md 文档完整

6. 选定方案

用户在讨论中确认了元↔分转换与费率结构，Agent 推荐策略模式（基点 bp 计算费率），FEE_RULES 使用 Object.freeze 防篡改。方案分支对比（策略模式 vs 规则引擎 vs 最简函数）已在讨论中完成。

7. 延后项（二期候选）

  • 部分退款状态追踪
  • 对账接口
